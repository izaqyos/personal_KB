# Writing Style

Read explicit style preferences, audience, purpose, facts, and intended action. Do not infer voice from a person's name. Lead with the point, use concrete verbs, and remove repetition while preserving uncertainty and attribution. Use casual abbreviations only when configured; formal reports should make facts, owner, and state easy to scan. Do not add promises, praise, blame, apologies, or assignments absent from the source. Return a paste-ready draft and separate factual ambiguities. Drafting does not authorize sending or clipboard changes.

Locate optional sources through private configuration described in [portable setup](../../README.md). Use available authenticated CLI tools/connectors or user-supplied material; report missing dependencies and stop dependent work rather than inventing evidence. Preserve user scope. External posting, deployments, destructive actions, and account changes require the user's authorization. Never store credentials, real rosters, or private runtime data in this package.
