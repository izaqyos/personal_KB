# Ownership Map

Read the canonical ownership map and evidence. Keep domain, team/role, contact reference, evidence date, and uncertainty together rather than scattering identifiers through skills. Distinguish permanent reporting changes from temporary assignments. Use recent code ownership as evidence, not a permanent-owner assumption. Propose narrow updates and verify dependent links after an authorized write. Personal identifiers belong in private configuration.

Locate optional sources through private configuration described in [portable setup](../../README.md). Use available authenticated CLI tools/connectors or user-supplied material; report missing dependencies and stop dependent work rather than inventing evidence. Preserve user scope. External posting, deployments, destructive actions, and account changes require the user's authorization. Never store credentials, real rosters, or private runtime data in this package.
