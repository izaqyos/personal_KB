# Sprint Prep

Resolve closing, planning, and following sprints from configured dates and live tracker state. Combine closing recap/carryover, next-sprint priorities and suggested assignments, capacity versus demand, dependencies, and following-sprint outlook; include next quarter when relevant. Paginate API queries. Virtualized boards omit offscreen rows: use canonical totals, label partial samples, and reconcile before asserting complete coverage. Date each source and separate old reports from today's state and committed scope from candidates. Return risks, gaps, and decisions without changing tracker state.

Locate optional sources through private configuration described in [portable setup](../../README.md). Use available authenticated CLI tools/connectors or user-supplied material; report missing dependencies and stop dependent work rather than inventing evidence. Preserve user scope. External posting, deployments, destructive actions, and account changes require the user's authorization. Never store credentials, real rosters, or private runtime data in this package.
